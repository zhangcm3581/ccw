让 Claude Code 跑在云端
合上笔记本，它还在干活

Claude Code 跑在服务器的 tmux 会话里，本地只留一个 cclaude 客户端。 断网、休眠、换设备都不打断正在运行的任务；本地项目目录与云端实时双向同步，你的编辑器照常用。

开始使用

怎么工作

  1. 一条命令装好客户端
    macOS / Linux / Windows 都是一行；装完 cclaude 全局可用。
  2. 选一个项目
    桌面上有个「cclaude 同步目录」，文件夹拖进去即成为项目； 已有的工程也可以就地登记，文件一个都不搬。
  3. 直接开始对话
    前台是云端的 Claude Code 终端，后台每 2 秒同步一轮当前项目目录。

特性

断线不中断

会话保活在云端 tmux 里。网络抖动、合盖休眠、换一台机器，正在跑的任务都不受影响， 重新连上就回到原来的现场。

本地目录双向同步

每 2 秒一轮清单比对：本地改动上云，云端产出回落本地。 两端同时改同一个文件时绝不静默覆盖，云端版本另存为冲突副本。

按目录隔离

每个本地目录在云端各有一份独立工作区，互不可见。 在 ~/code 与 ~/work 里跑是两件事，不会串。

项目相互隔离

每个项目独立容器、独立 workspace 与磁盘配额；一张 CDK 只能访问它自己的项目， 看不到也碰不到别人的。

云端占用自己管

客户端里能看到云端每份副本的大小，勾掉不再用的就释放空间—— 删的只是云端副本，本地文件一个不动。

额度始终可见

终端底部常驻一行：上下文用量、5 小时与一周窗口的剩余比例，以及到下次重置还有多久。 不用猜还能干多少。

它不做什么

凭据类文件不参与同步——.env*、.ssh/、.aws/ 等一律排除， .git/、node_modules/ 与符号链接同样不同步。
这是硬边界，不是可以关掉的选项。
